# Report Schema

`report.json` contains a top-level object with `metadata` and a `phases` array.
[`report-schema.schema.json`](report-schema.schema.json) is the machine-readable
draft 2020-12 schema. It keeps phase metrics extensible but gives typed coverage
for the core `colorspace_mapping` diagnostics used by validation tooling.

Top-level `metadata` is stable and identifies the run that produced the report:

| Field | Notes |
|-|-|
| `report_schema_version`, `pipeline_schema_version` | Compact schema identifiers for tooling. The current report schema is version 4: version 3 introduced exact executable identity and version 4 adds required exact-byte delivery-artifact binding. |
| `generated_at`, `generated_at_unix_ms` | Report/run creation time. |
| `package_name`, `package_version`, `binary_name` | Named package/build identity. |
| `binary_path`, `binary_sha256`, `binary_file_size_bytes`, `binary_identity_status`, `binary_identity_error` | Exact executable identity, introduced in report schema v3. The current executable is hashed once per process and reused for every report. `verified_sha256` with a nonempty path, positive size, and 64-hex digest is required where exact implementation identity matters; older reports remain readable with these fields absent. |
| `working_directory` | Process working directory. |
| `cli_args` | Invocation arguments captured by the process. |
| `output_dir`, `output_path` | Intended output directory and final render path. |

Each phase has:

| Field | Stability | Notes |
|-|-|-|
| `name` | Stable | Phase identifier. |
| `success` | Stable | `false` means the phase failed or rejected its candidate. |
| `confidence` | Stable | Phase confidence in `[0, 1]`, sometimes capped by upstream base confidence. A successful phase can intentionally report `0.0` when its evidence is not applicable rather than measured. |
| `duration_ms` | Stable | Wall-clock phase duration. |
| `metrics` | Mixed | Phase-specific fields. Stable fields are listed below. |
| `warnings` | Stable | Human-readable diagnostics. Text can change; presence and phase are more stable than exact wording. |
| `errors` | Stable | Human-readable failure reasons. |

## Stable Metrics

`load`

| Field | Notes |
|-|-|
| `input_count`, `inputs`, `components[]` | Ordered caller inputs plus per-component path, oriented shape, and decode diagnostics. One or more inputs are supported. |
| `component1_decode`, `component2_decode` | Per-component source layout and working-range diagnostics. |
| `decode_fidelity_status`, `decode_fidelity_evaluated`, `full_fidelity_component_count` | Phase-level aggregation across every input. Status is `all_components_full_declared_decode_fidelity`, `mixed_component_decode_fidelity`, or `no_component_full_declared_decode_fidelity`; phase confidence is the weakest component rather than file-I/O success. |
| `components[].decode.decode_fidelity` / `component*_decode.decode_fidelity` | Per-component status, confidence, component scores, and exact limiters. `full_declared_decode_fidelity`, `limited_declared_decode_fidelity`, and `insufficient_declared_decode_fidelity` distinguish an exact declared working representation from a usable but limited one or missing essential RGB/orientation evidence. |
| `components[].decode.decode_fidelity.precision_confidence` | `min(source_bits_per_sample, working_bit_depth) / max(source_bits_per_sample, working_bit_depth)`. Expanding an 8-bit source into a 14-bit working buffer therefore reports `8/14`; rescaling preserves the original samples but cannot manufacture the missing tonal levels. |
| `components[].decode.decode_fidelity.channel_layout_confidence`, `orientation_confidence`, `dng_level_confidence` | Exact declared evidence for independent RGB channels, required orientation materialization, and usable DNG black/white-level metadata. The component confidence is their minimum together with precision confidence. |
| `components[].decode.decode_fidelity.limiters` | Machine-readable reasons such as `source_precision_upscaled_without_added_information`, `source_precision_downscaled_with_information_loss`, `non_rgb_source_channels_expanded_to_rgb`, `required_orientation_not_materialized`, and `invalid_dng_level_metadata`. |
| `components[].decode.decoded_pixel_sha256` | Deterministic SHA-256 over the final normalized, effectively oriented samples plus dimensions, channel count, and working bit depth. Fixture orientation approval pins this digest so any decoded-pixel, precision, dimension, metadata transform, or explicit correction drift fails exactly. |
| `components[].decode.source_orientation_materialized_decoded_pixel_sha256` | Binding of the pixels immediately after EXIF/DNG orientation and before any explicit semantic correction. It equals the final digest when correction is `none`. |
| `components[].decode.orientation` | Source-metadata evidence only: nullable EXIF/DNG `tag_value`, named metadata `transform`, `applied`, original `source_width`/`source_height`, metadata-oriented `output_width`/`output_height`, and decision reason. |
| `components[].decode.orientation_correction` | Explicit metadata-relative semantic-upright correction. It records the requested and applied transform, before/after dimensions, composed `effective_tag_value`/`effective_transform`, both pixel hashes, and reason. Correction occurs after metadata materialization but before scanner linearization, deskew, border detection, or stitching. `none` never claims that semantic uprightness was inferred. |
| `components[].decode.effective_orientation_tag` | Composed D4/EXIF transform from original scanner coordinates to the final corrected component. Scanner spatial calibration uses this value so a manual correction does not move shading or flare models into the wrong coordinate frame. |
| `component*_decode.dng_metadata` | Present for DNG inputs when primary-IFD metadata is available. It records scanner/software identity (`make`, `model`, `unique_camera_model`, `software`), DNG colour tags (`color_matrix1`, `color_matrix2`, `as_shot_neutral`, `black_level`, `white_level`, calibration illuminants), matrix condition numbers, and non-fatal metadata parse warnings. |

Load confidence is declared decode-fidelity evidence strength, not an empirical probability of image
quality and not an indication that file I/O failed. A successfully decoded low-precision input remains
processable, but it no longer receives a fabricated perfect score merely because its samples could be
expanded into the working integer range.

`border_removal`

| Field | Notes |
|-|-|
| `border_decision_status`, `border_evidence_evaluated`, `supported_component_count`, `all_components_have_supported_applied_crop` | Phase-level evidence state. Status is `all_components_supported_applied_crop`, `partial_components_supported_applied_crop`, or `no_component_supported_applied_crop`. Evaluation can complete successfully without finding a supported crop. |
| `components[].crop.border_decision_status`, `border_evidence_evaluated`, `applied_crop_evidence_supported`, `applied_edge_count` | Per-component distinction among a measured applied crop, a measured no-op (`no_crop_no_convincing_dead_zone`), an image too small to evaluate, an unsafe full-image crop proposal, and `no_crop_with_unresolved_strong_edge_candidate` / `partial_crop_with_unresolved_strong_edge_candidate`. A no-op is not presented as proof that no scanner border exists; an unresolved strong candidate requires final geometry review. |
| `confidence`, `confidence_basis`, `confidence_definition` | Each applied edge score is the minimum of three normalized acceptance signals: strong-line count (full support at four lines), peak luminance separation (full support at 1.5x the strong-gap threshold), and boundary transition (full support at the derivative threshold). Component confidence is the minimum applied-edge score; phase confidence is the minimum component score. No supported applied crop, unsafe rejection, or non-evaluation reports `0.0`. This is evidence strength, not an empirical probability of crop correctness. |
| `top_confidence`, `bottom_confidence`, `left_confidence`, `right_confidence` | Per-edge evidence strengths. An edge that was not cropped reports `0.0`; successful control flow never manufactures confidence for a no-op. |
| `*_boundary_transition_delta`, `row_*_threshold`, `column_*_threshold`, `*_strong_rows`, `*_peak_lum_gap`, `*_peak_*_delta` | Exact raw evidence and thresholds behind each score. Existing removed-pixel counts and content reference statistics remain available at the same level. |
| `*_overwhelming_support_fallback_used` | Per-edge evidence that automatic crop used the conservative gradual-boundary fallback: at least eight strong lines, at least 4x the strong luminance-gap threshold, and aggregate boundary change at least 35% of the ordinary derivative threshold. This is recorded rather than hidden inside a generic accepted crop. |
| `*_unresolved_strong_candidate` | Per-edge evidence that at least four ordinary low-variance strong lines formed a flat run (luminance span no more than 0.75x the strong-gap threshold) with at least a 3x luminance gap, but boundary-transition support was too weak even for the conservative fallback. Curved/high-variance admission or a smooth full-frame gradient alone cannot create this delivery block. The edge remains uncropped and the final render is blocked for geometry review. |
| `review_required`, `review_reason` / `review_reasons` | Diagnostic review is raised for images too small to evaluate, unsafe full-image crop proposals, unresolved strong edge candidates, or an impossible applied crop with invalid evidence. A normal no-border/no-crop result remains a warning and zero-evidence state, not an automatic final-render block. Border review reasons are propagated into the final save/delivery geometry gate. |

`stitch`

| Field | Notes |
|-|-|
| `decision` | Pair mode uses `accepted`, `rejected`, or `skipped_pre_score`; sequence mode uses `accepted_sequence` or `rejected_sequence`; one input uses `skipped_single_input`. |
| `stitch_evidence_evaluated`, `confidence_basis`, `user_override` | Provenance for a skipped stitch phase or pre-score decision. `skipped_single_input` reports no evaluated stitch evidence, `not_applicable_single_input`, and phase confidence `0.0`. A forced skip is an explicit user-authoritative override; an automatic negative-film topology skip retains its measured topology confidence. Routing priors that merely trigger overlap scoring are not described as completed stitch evidence. |
| `input_count`, `ordering.inferred_order` | Sequence input count and one-based left-to-right order inferred from the validated directed overlap graph. |
| `ordering.accepted_adjacent_edges`, `ordering.required_adjacent_edges`, `ordering.all_adjacencies_validated` | Whether the selected ordering path has robust evidence for every adjacency. |
| `ordering.pairwise_edges[]` | Directed pairwise objective/NCC/overlap/offset evidence and explicit rejection reasons used for N-input ordering. |
| `ordering.pairwise_edges[].expected_vertical_offset_px`, `pair_merges[].expected_y_offset`, `vertical_crop_origins` | Coordinate offsets induced by independently removed top borders. Translation search remains centered on these origins, with `max_y_offset` reserved for residual mechanical drift. |
| `pair_merges[]` | Incremental mosaic merge reports. Every merge must pass normal stitch gates; a rejected step invalidates the complete sequence. Each accepted pair report retains its own exposure and seam-blend evidence. Compact validation summaries conservatively aggregate these records: common exposure models remain named, differing models become `sequence_mixed`, normalized offsets and seam residuals use worst cases, supported detail scales use the minimum, and non-identity held-out validation must pass for every affected merge. |
| `preserved_full_valid_union`, `target_crop_disabled` | Confirms that accepted pair or sequence geometry was not cropped back to one component's dimensions. Rejected geometry reports `preserved_full_valid_union=false`. |
| `chosen_hypothesis` | Selected ordering such as `[1|2]` or `[2|1]`, when scored. |
| `requested_transform`, `transform_model_used` | Requested and actual alignment model. |
| `hypotheses[].ordering` | Hypothesis label. |
| `hypotheses[].accepted` | Candidate acceptance state. |
| `hypotheses[].rejection_reason` | Explicit rejection reason, when rejected. |
| `hypotheses[].search.selection_reason` | Why the candidate was selected for validation. |
| `hypotheses[].search.max_overlap_considered` | Largest overlap searched. |
| `hypotheses[].search.top_candidates[].correspondence_score` | Image-evidence score before priors. |
| `hypotheses[].search.top_candidates[].prior_weight` | Conservative prior applied to the candidate. |
| `hypotheses[].validation.evidence_score` | Dense validation evidence. |
| `hypotheses[].validation.prior_weight` | Validation prior. |
| `hypotheses[].validation.overlap_support_score` | Width-support score. |
| `hypotheses[].validation.vertical_offset_plausibility_score` | Vertical-offset plausibility. |
| `hypotheses[].validation.local_consistency_score` | Dense local-window consistency. |
| `hypotheses[].validation.local_dx_plane_px`, `local_dy_plane_px` | Weighted overlap displacement planes `[intercept, x_slope, y_slope]`; coherent non-zero slopes can trigger auto affine evaluation. |
| `hypotheses[].validation.plausibility_score` | Combined plausibility score. |
| `runtime.total_ms` | Total stitch function runtime in milliseconds. |
| `runtime.translation_evaluation_ms` | Time spent evaluating the two translation hypotheses. |
| `runtime.native_affine_attempted`, `runtime.native_affine_ms` | Whether evidence triggered native affine evaluation and its runtime. |
| `runtime.homography_attempted`, `runtime.homography_ms` | Whether the OpenCV/homography path was attempted and its runtime. |
| `native_affine`, `affine_validation` | Native affine model-selection evidence. The candidate is seeded by bounded small-angle search, optionally refined to six parameters, and accepted only when disjoint held-out NCC and registration error improve by the reported thresholds. `rotation_search_limit_deg` and `rotation_search_boundary_hit` make the convergence guard explicit: a candidate at the configured rotation edge is rejected rather than treated as a valid optimum. Accepted reports also include rotation, scale, shear, correspondence/inlier counts, the right-to-left matrix, and the single-resample interpolation policy. `native_affine` is retained on translation fallback; `affine_validation` is present on accepted affine output. |
| `homography_feature_validation`, `hypotheses[].validation.homography_feature_validation` | Spatially disjoint feature-fit evidence. Lowe-filtered SIFT correspondences are partitioned by 4x4 whole source cells. The primary transform is fit only on checkerboard training cells with normalized DLT and deterministic RANSAC; held-out match/cell counts, forward cross-inlier ratio and residuals, reverse held-out-fit validation, maximum cross-fit transform disagreement, decision, and reason are reported. The top-level object is present for accepted homography output; the hypothesis object retains rejected attempts. |
| `homography_spatial_validation` | Independent image-domain score evidence after feature cross-fit. The candidate must beat the validated translation transform on both checkerboard NCC partitions, meet per-split and mean registration-error-reduction floors, have enough samples in each partition, and differ meaningfully from translation. `model_selection_limit` records the separation between training-cell feature fitting, reverse feature cross-fit, and image-domain validation. |
| `valid_union_pixel_count`, `canvas_void_pixel_count`, `multiband_overlap_rectangle`, `overlap_outside_multiband_pixel_count` | Accepted affine/projective canvas and mask diagnostics. Valid pixels are tracked by an explicit warp mask, not inferred from RGB zero; the largest fully valid overlap rectangle receives multiband blending and only irregular edge remnants use bounded row-wise feathering. |
| `compositor`, `interpolation`, `projective_matrix_right_to_left`, `projective_matrix_right_to_canvas`, `left_canvas_origin` | Accepted homography composition policy and coordinate transforms. The OpenCV matrix is inverted into right-to-left full-image coordinates, then a bounded canvas shift is applied. Pixels receive one pure-Rust Catmull-Rom bicubic resample. |
| `seam_exposure_correction.mode` | Currently `auto` for conditional overlap-derived compensation. |
| `seam_exposure_correction.model`, `applied` | Selected photometric model: `identity`, `gain_only_scalar`, `gain_only_rgb`, conservative `gain_offset_rgb`, held-out-validated `gain_spatial_y_rgb` / `gain_offset_spatial_y_rgb`, planar `gain_spatial_xy_rgb` / `gain_offset_spatial_xy_rgb`, or bounded `gain_spatial_quadratic_xy_rgb` / `gain_offset_spatial_quadratic_xy_rgb`; whether it was applied to the right component before blending. `sequence_mixed` is a compact-validation aggregate label, not a per-merge fit model. |
| `seam_exposure_correction.reason` | Decision reason for applying or rejecting correction. |
| `seam_exposure_correction.sample_count`, `valid_sample_ratio` | Trustworthy overlap samples used after clipping, near-black, low-texture, and outlier rejection. |
| `seam_exposure_correction.gain_rgb`, `gain_luma` | Applied gain. Identity values mean no correction was applied. |
| `seam_exposure_correction.spatial_gain_log_slope_y_rgb`, `spatial_gain_log_slope_y_luma` | Applied vertical log-gain slope over normalized overlap `y=-1..1`. Zero is a constant model. The field is exponential, positive, and clamped to its measured top/bottom support during composition. |
| `seam_exposure_correction.spatial_gain_top_rgb`, `spatial_gain_bottom_rgb` | Applied endpoint gains. Both endpoints must remain within the automatic 0.80–1.25 gain bounds and the RGB-spread limit. `estimated_spatial_gain_*` retains the rejected or accepted candidate for audit. |
| `seam_exposure_correction.spatial_offset_slope_y_rgb`, `spatial_offset_slope_y_rgb_normalized`, `spatial_offset_top_rgb*`, `spatial_offset_bottom_rgb*` | Applied vertical additive field in source and normalized sample units. The center is `offset_rgb`; endpoints are clamped outside overlap support and each must remain within 5% of the sample range. Zero values identify every simpler model. |
| `seam_exposure_correction.spatial_gain_log_slope_x_rgb`, `spatial_offset_slope_x_rgb*`, `spatial_gain_corners_rgb`, `spatial_offset_corners_rgb*` | Applied horizontal plane terms and the four evaluated overlap corners. Planar coordinates are normalized over the observed overlap rectangle and clamp outside it; no unsupported full-scan extrapolation occurs. |
| `seam_exposure_correction.spatial_gain_log_quadratic_{xx,xy,yy}_rgb`, `spatial_offset_quadratic_{xx,xy,yy}_rgb*` | Applied curvature coefficients in normalized overlap coordinates. Gain uses log space; offsets use sample units plus normalized report mirrors. All coordinates clamp to the measured overlap rectangle before evaluating `[1,x,y,x²,xy,y²]`. |
| `seam_exposure_correction.spatial_2d_validation` | Candidate and gate evidence for planar gain and gain+offset fields: whole-cell training/held-out row and column counts, direct window consistency, overall/horizontal slope agreement, independently fitted center drift, four-corner estimates, held-out scores, best simpler model, improvement, acceptance, and rejection reasons. Each split needs at least four rows and three columns; the selected plane must beat the best accepted lower-dimensional model by max(0.0025, 20% of its score). |
| `seam_exposure_correction.spatial_2d_validation.quadratic` | Curvature-specific evidence: fixed basis and ridge strength, minimum/current split support, training/held-out design condition numbers, unseen-window consistency, independent curvature-coefficient agreement, maximum full-field disagreement, curvature signal, fitted coefficients, 9x9 support-grid gain/offset extrema, held-out scores, best simpler model, complexity improvement, acceptance, and exact rejection reason. Each split needs at least 18 windows, six rows, and five columns. The grid plus exact quadratic edge/interior extrema keeps gains within 0.80–1.25 and bounds RGB spread/offsets; the selected model must beat the best accepted simpler model by max(0.0025, 20% of its score). |
| `seam_exposure_correction.offset_rgb`, `offset_luma`, `offset_rgb_normalized` | Applied additive correction in source sample units and normalized to the declared input range. Zero means no additive correction. The automatic bound is 5% per channel. This is overlap-derived flare/black compensation, not an independently measured scanner black calibration. |
| `seam_exposure_correction.delta_luma_before`, `delta_luma_after` | Signed log-luma seam delta before and after the applied correction. |
| `seam_exposure_correction.delta_rgb_before`, `delta_rgb_after` | Signed per-channel log seam deltas before and after the applied correction. |
| `seam_exposure_correction.seam_score_before`, `seam_score_after` | Robust seam mismatch score; lower is better. |
| `seam_exposure_correction.clipped_high_before`, `clipped_high_after` | Per-channel high-clipping ratios in the overlap before and after the applied correction. |
| `seam_exposure_correction.clipped_low_before`, `clipped_low_after` | Per-channel low-clipping ratios in the overlap before and after the applied correction. |
| `seam_exposure_correction.training_*`, `held_out_*` | Whole overlap windows are split spatially before fitting. Counts and identity/gain/gain+offset/spatial-gain held-out scores expose the disjoint evidence used for model selection. |
| `seam_exposure_correction.gain_offset_consistent_window_ratio`, `held_out_validation_passed`, `gain_offset_rejection_reason` | Spatial agreement, final held-out gate, and the explicit reason the more flexible additive model was accepted or refused. Gain+offset must materially beat both identity and gain-only on held-out windows without exceeding gain/offset/clipping limits. |
| `seam_exposure_correction.spatial_distinct_*_rows`, `spatial_consistent_window_ratio`, `spatial_slope_agreement_ratio`, `held_out_spatial_improvement_over_best_constant`, `spatial_rejection_reason` | Evidence and gate for the vertical RGB field. Training and held-out splits each need at least three represented rows; unseen windows must agree with both predicted gains and slope direction/magnitude; the field must materially beat the best accepted constant model without endpoint, RGB-spread, or clipping violations. Planar x/y candidates are audited separately in `spatial_2d_validation` and never extrapolate beyond the observed overlap support. |
| `seam_exposure_correction.spatial_affine_*`, `held_out_spatial_gain_offset_seam_score`, `held_out_spatial_gain_offset_improvement_over_best_simpler`, `spatial_gain_offset_rejection_reason` | Evidence and gate for the vertical gain+offset field. Robust nonlinear training and held-out fits each require four signal-rich rows. At least 65% of held-out windows must improve directly, at least 2/3 of material gain/offset slopes must agree, center offsets must agree within 1.2% of range, and the model must beat the best accepted simpler model by max(0.0025, 20% of its score), while retaining all gain/offset/clipping bounds. |
| `seam_blend.mode`, `applied`, `reason` | Translation, native affine, and accepted homography stitching use `seam_aware_multiband`: a minimum-cost low-detail seam plus bounded multiscale blending. |
| `seam_blend.overlap_width_px`, `overlap_height_px`, `transition_width_px`, `pyramid_levels`, `pyramid_radii_px`, `processing_roi_x` | Exact overlap and bounded multiscale processing geometry. |
| `seam_blend.seam_path_*_normalized_cost`, `seam_path_min_x`, `seam_path_max_x`, `seam_path_mean_x` | Seam-path location and normalized energy diagnostics. |
| `seam_blend.overlap_mean_abs_difference`, `overlap_p95_abs_difference` | Normalized pre-blend overlap mismatch. These are scene/scan dependent and should be fixture-gated, not treated as universal limits. |
| `seam_blend.output_seam_gradient_p95`, `source_seam_gradient_p95`, `output_to_source_seam_gradient_ratio` | Measured seam-gradient continuity. A ratio below 1 means the composited seam p95 is lower than the corresponding source discontinuity. |
| `seam_blend.detail_consistency` | Multi-scale overlap detail evidence. Normalized luma high-pass RMS energy is measured at 1, 2, and 4 pixel radii in 6x6 whole-cell checkerboard partitions. Per-scale training/held-out energies, right/left and symmetric ratios, direction consistency, cross-split agreement, `decision_supported`, decision thresholds, and reasons are retained. A severe mismatch needs at least four signal-rich windows in each split, at least a 2x ratio in both, 75% directional consistency, no more than 1.35x cross-split ratio disagreement, and repetition on two scales. Fewer than two supported scales cannot validate continuity and therefore also request review. |
| `seam_blend.review_required`, `review_reason` | Fail-closed seam-quality result. It is true when repeated disjoint detail evidence indicates a focus/grain/texture transition, when fewer than two detail scales have support, or when the composed seam-gradient p95 exceeds 1.05x the source reference. The stitched union is preserved for diagnosis, the stitch phase warns and caps confidence at 0.35, and pipeline save status becomes `blocked_geometry_review`. No automatic blur/sharpen operation is inferred from this diagnostic. |

`scanner_linearization`

| Field | Notes |
|-|-|
| `skipped`, `application_stage` | Whether a held-out-validated scanner model was available. Applied models run as `per_component_before_border_crop_classification_and_stitch`; they are never first applied to a completed mosaic. |
| `coordinate_domain` | Applied scans use the full decoded component while spatial coordinates refer to the original scanner frame. |
| `components[]` | Per-input model ID, source/output bit depth, original scanner dimensions, orientation mapping, curve extrapolation, clipping, and shading-range diagnostics. |
| `components[].diagnostics.coordinate_domain`, `orientation_tag` | `original_scanner_frame_via_inverse_exif_orientation` for any composed metadata-plus-explicit transform; otherwise `full_component_scanner_frame`. The reported tag is the effective transform, not merely the source metadata tag. |
| `maximum_channel_curve_extrapolated_ratio`, `maximum_channel_clipped_ratio` | Worst component/channel ratios across the input set. |
| `base_color_before`, `base_color_after` | Only a manual source-code base override needs center-reference transformation here. Automatically detected film base is measured after per-component linearization. |
| `selection_without_observed_base` | Scanner selection evidence used before geometry. Roll/base-dependent calibration is loaded again later; any change in the selected scanner linearization causes an explicit consistency failure. |

`base_detect_classify`, `working_image_select`, and `density_inversion`

| Field | Notes |
|-|-|
| `base_detect_classify.classification_status` | `evaluated_negative_film_rebate_topology` when negative-film component evidence was measured, or `not_applicable_positive_input` when that classifier was deliberately bypassed for already-positive input. |
| `base_detect_classify.classification_evidence_evaluated`, `confidence_basis` | The evaluated boolean and provenance for the phase confidence. Positive input reports `false`, `not_evaluated`, and phase confidence `0.0`; phase `success=true` means the bypass completed correctly, not that classification quality was perfect. Negative input reports measured rebate topology and uses the maximum component measured classification confidence. The same status, evaluated flag, basis, and confidence are retained per component. |
| `input_mode` | `negative` for the default negative-film workflow, or canonical `positive` for `--input-mode positive`, `slide`, or `positive-slide`. |
| `working_image_select.confidence` | Negative mode uses the base-confidence signal that caps downstream phases. Positive mode reports input-mode suitability confidence: `0.0` when the channel-ratio/orange-mask inspection finds the declared-positive input strongly negative-like, otherwise `1.0`. |
| `raw_base_confidence` | Direct working-crop rebate confidence from left/right or top/bottom base evidence. |
| `raw_base_proxy_confidence`, `raw_base_support_fraction` | Low-confidence high-transmittance fallback evidence when no edge/base strip is detected. |
| `base_estimate_source` | Where the base estimate came from, such as `working_edges`, `horizontal_base_region`, `vertical_base_region`, `component_consensus`, roll-level `roll_consensus_base`, manual `manual_base_color_override`, or low-confidence `high_transmittance_fallback`. Positive input reports `not_applicable_positive_input` because no film-base density inversion is performed. |
| `base_estimate_reason` | Human-readable reason for the selected base estimate. |
| `positive_input_inspection`, `input_mode_suitability_status`, `input_mode_suitability_evaluated`, `input_mode_review_required`, `input_mode_review_reason` | Present in positive mode. Strict validation rejects population hierarchy, model-geometry, disabled-effect, trust, positive mean-chroma, and DeltaE-cap contradictions. |
| `noise_reduction_requested_enabled`, `noise_reduction_requested_strength`, `noise_reduction_requested_scale` | Exact independent film-grain control requested by batch CLI, UI, or review sidecar. Reduction defaults off and render intent never changes it implicitly. Strength is normalized to `0..1`; scale is normalized to `0.5..4`. |
| `noise_reduction_enabled`, `noise_reduction_reason`, `noise_reduction_radius`, `noise_reduction_chroma_amount`, `noise_reduction_luma_amount` | Whether reduction actually ran, why it did or did not, and its effective spatial/amount settings. An enabled request with zero strength or an image smaller than its window reports disabled without pretending to have changed pixels. |
| `noise_reduction_applied_ratio`, `noise_reduction_structure_gate_start`, `noise_reduction_structure_gate_end`, `noise_reduction_structure_excluded_ratio`, `noise_reduction_texture_limited_ratio`, `noise_reduction_saturation_limited_ratio`, `noise_reduction_mean_abs_*`, `noise_reduction_max_abs_*` | Selectivity and effect diagnostics for the final optional pass. `applied_ratio` is the materially active mask population, not a claim that every selected pixel changed after a zero residual. The multiscale structure gate feathers from 0.018 to the independent 0.035 luminance-detail contrast floor; pixels at or beyond the floor, protected by coherent opponent-colour structure, or lacking a complete filter window are bypassed exactly, including f32 reconstruction, and counted by `structure_excluded_ratio`. Saturation limiting is an effective shadow-relaxed multiplier rather than a label-only diagnostic. Mean/max deltas measure the resulting channel effects. The pass preferentially suppresses local high-frequency chroma residuals and mild shadow luminance grain; frame-level grain evidence never scales the locally blurred chroma base. |

| `grain_reduction.requested`, `grain_reduction.effective`, `grain_reduction.before`, `grain_reduction.after`, `grain_reduction.effect` | Structured audit record containing requested controls, effective settings/protection (including the exact structure gate and excluded population), complete grain diagnostics before and after, and residual/delta effect sizes. This is the preferred record for proving that an optional reduction did—or did not—change the render. |
| `grain_reduction.detail_retention` | Diagnostic-only pre/post preservation proof over sampled multiscale-coherent edges. It records the opponent-colour/luminance method, evaluation/support state, filter-scale probe radius, sampling stride, per-channel probe counts/support, median and p10 contrast retention, thresholds, decision reason, and review reason. Opponent-colour coherence also expands the live denoise protection mask across the filter footprint, preventing isoluminant coloured edges from being treated as chroma grain. A channel needs at least 64 probes; supported median retention must remain at least 0.90 and p10 at least 0.70. Missing coherent structure is reported as unsupported, not trusted and not automatically harmful. |
| `noise_reduction_detail_decision_supported`, `noise_reduction_detail_review_required` | Flat compatibility fields for the structured retention decision. A supported failure or an unsupported requested grain claim sets requested-grain evidence confidence to `0.0`; a supported harmful result propagates to final `render_review_status=review_required_grain_detail`. The requested output is retained for diagnosis rather than silently replaced. |
| `render_quality_bands` | Grouped overall, shadow, midtone, bright-neutral, and bright-saturated band diagnostics. |
| `high_frequency_grain.sample_count`, `sample_stride` | Sampled local residual population for grain diagnostics. |

| `high_frequency_grain.flat_luma_structure_max`, `flat_sample_count`, `flat_sample_ratio` | Low-structure subset used to separate flat-field grain from real scene edges or texture. |
| `high_frequency_grain.flat_luma_residual_p95`, `flat_chroma_residual_p95`, `flat_chroma_to_luma_p95_ratio` | High-frequency residual p95 values measured only in low-structure samples. Prefer these when deciding whether smooth areas still show distracting grain. |
| `interactive_controls_applied` | Present and `true` for explicit `scanstitch-ui` saves. |
| `interactive_controls` | Applied `exposure_ev`, `midpoint`, `slope`, `toe_lift`, `shoulder_max`, `grain_reduction_enabled`, `grain_reduction_strength`, and `grain_reduction_scale` for `scanstitch-ui` saves. Older schema-v1 sidecars without grain fields deserialize to off / `0.5` / `1.0`. |

`--require-reviewable` does not stop at these self-reported save metrics. After the report and
artifacts are retained, the main CLI and validation harness independently reopen `output.tiff` to
require the reported positive dimensions, RGB16 unsigned storage, matching ICC profile, and—for
schema-v4 reports—the exact declared SHA-256. They
also reopen every promised master and review proof: the master must be same-sized RGB32 IEEE float
with the scene-referred description and linear-ProPhoto profile; the proof must be same-sized RGB8
PNG with the canonical sRGB profile and supported zero-excursion perceptual gamut-map diagnostics.
Every requested schema-v4 auxiliary artifact must also match its declared exact-byte SHA-256.
An explicit zero stale-artifact count is also required.
Missing or contradictory artifact evidence rejects delivery even when the status/boolean pair says
reviewable.

This is an integrity binding, not authentication. It detects a missing, modified, or substituted
artifact while the report is unchanged, including a valid same-shape TIFF/PNG with matching
storage and ICC semantics. The report itself is not signed: an actor able to rewrite both the
report and artifact, or deliberately downgrade its schema version, is outside this gate's trust
boundary. A fixture-pinned, hash-bound completed render-review manifest is the stronger acceptance
record, but its reviewer identity is still an organizational provenance claim rather than a
cryptographic signature.

Human photographic acceptance is intentionally outside this self-reported pipeline schema. Use
`scanstitch-validate --write-render-review` to derive a non-approved, hash-bound package from the
report. [`render-review.schema.json`](render-review.schema.json) binds the ordered source/decode
evidence and every delivery artifact, while fixture coverage rechecks the technical gate and the
completed reviewer decisions before counting it. Schema version 2 additionally requires every
grain-applicable review to bind an exact grain-off report and its three delivery artifacts. The
validator requires matching decoded inputs and normalized non-grain render arguments, a technically
reviewable control, identical valid executable fingerprints from schema-v3-or-newer reports, and byte-identical
scene-referred masters; stale, substituted, differently built, or differently graded controls
invalidate approval.

## Compact Validation Evidence

`scanstitch-validate` adds stable aggregate groups to `summary.json` so fixture contracts do not have
to infer multi-component evidence from individual phase records.

| Summary group | Stable evidence |
|-|-|
| `input_orientation` | Input/component counts, completeness, and per-component index, tag value, named transform, application flag, source dimensions, and decoded dimensions. |
| `deskew` | `input_count`, `component_count`, `all_components_reported`, `all_components_applied`, and `minimum_component_retained_area_ratio`, in addition to the single/aggregate deskew decision fields. |
| `border_crop` | Component/report counts, `all_components_cropped`, total and minimum removed-edge counts, minimum/maximum retained-area ratios, rejected-crop warning count, and per-component top/bottom/left/right removals plus input/output dimensions. |
| `negative_reconstruction` | Input mode, inversion skip/confidence, selected response model/source/acceptance/review, crosstalk and curve models, measured model ID/confidence, held-out RMS/maximum CIEDE2000 and unit-slope improvement, density-noise gain, runtime reconstruction review, signed headroom, extrapolated-pixel ratio, and interpolation method. |
| `render` | Final `render_review_status`/`render_reviewable` plus the copied tone-output review flag, reason, confidence status, evidence confidence, rendered range, relative range retention, and maximum high/low clipping. The compact record therefore cannot discard a final tone-output review decision. |
| `tone` | Tone confidence/status, complete tone-output evidence and limiter provenance, input/fitted/rendered ranges, relative retention, clipping maxima, existing colour-protection/band diagnostics, and optional grain evidence. |

Tracked summary baselines may optionally pin the final render review state and tone-output status,
confidence, ranges, retention ratio, and clipping maxima. Old baselines omit these fields and remain
readable; newly written baselines preserve them, and both report comparison paths emit explicit
`tone_output_*` regression issues. `--fail-on tone` selects those issues as well as chroma-compression
changes.

Roll-suite JSON mirrors the complete tone-output record on each `frames[]` entry and aggregates
final-render statuses, tone-output statuses, and review reasons under `review`. A false or missing
final-review decision and a true or missing tone-output decision create explicit roll issues. Roll
comparisons preserve per-frame status/review transitions plus confidence, relative-range, and
clipping deltas; missing legacy baseline fields are nonasserting, while loss of established current
evidence is reported.

Fixture-suite entries mirror these as nested `geometry_preparation`, `input_orientation`, and
`negative_reconstruction` expected/actual records. Geometry evidence includes the expected/actual
signed correction, correction tolerance, actual indexed crop summaries, expected per-component
four-edge pixel targets/tolerances, and exact orientation tag/transform/application/dimension
records. Missing old-report fields deserialize to defaults; they do not satisfy a complete strict
contract.

## Diagnostic Fields

Fields not listed as stable are diagnostic. They are useful for investigation, but may be renamed or reshaped while the pipeline is still being tuned. The most likely fields to move are detailed stitch search internals, exact warning text, debug artifact paths, and experimental candidate-ranking scores.
